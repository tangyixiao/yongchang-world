## Unreleased — save-based checkpoint export

- Added `tools/save_checkpoint_export.py`, the missing half of Gate 4: it reads a checkpoint year's numbers out of a save the game itself wrote, so the 450-row matrix no longer depends on someone transcribing panels. It derives `rank` from `country_rankings`, `population` from the country's own `pop_statistics` strata (lower + middle + upper — the figure the country panel shows), `market` as the tag of the country that owns the market, `wars` as the wars still being fought (`peace_date = 1.1.1`), `subjects` as the subject pacts the country is the overlord of, and `error_count` from the run's `error.log` line count. Nothing is estimated: a missing core country, a missing ranking row, or a market with no owner fails the export by name instead of producing a plausible number.
- Two independent population readings are cross-checked, because one wrong section read is the failure mode that would quietly poison 450 rows: the strata total is compared against the sum of `pops.database` workforce + dependents per owned state, and a gap wider than 0.5% is reported. On a real 123 MB 1.13.11 save the two agree for all ten countries to within 0.01%, which is pop-accounting rounding, not a parsing bug. Where `pop_statistics` is absent the tool falls back to the pops sum and records which method each row used in `population_source`.
- The subject-action vocabulary is read from the installed game's `common/subject_types/*.txt` (`diplomatic_action`) rather than listed by hand, and the overlay/subject direction is grounded: `targets.first` is the overlord, per vanilla's `c:CHI ?= { create_diplomatic_pact = { country = c:TIB type = vassal } }` showing up in a real save as `vassal first=156 second=167`. The extraction was verified against that save on live data: Brazil 2 ongoing wars, BIC 42 subjects, GBR 20, CHI 3.
- Guard rails are deliberate. A save dated outside 1846/1866/1900 is refused, so a mid-campaign autosave cannot be mislabelled as a checkpoint; `--any-date` exists only to diagnose such a save and the export then records `checkpoint_eligible: false`. `--year` asserts rather than rewrites, and never converts a save's own date. The JSON carries the save's path, size and sha256, in-game date, game version and mounted mods, so every recorded row traces back to one file.
- `tests/test_save_checkpoint_export.py` adds 24 tests over a miniature save written in the game's real shape, covering the happy path, every refusal, the population cross-check, and a round-trip through `record_checkpoint.load_rows` — the CSV this tool writes is accepted by the existing recorder unchanged. Full suite passes 341 tests.

## Unreleased — history root keys (silent no-op fix)

- Fixed five `common/history/diplomacy/` files that the game was discarding in full. Vanilla loads every `common/history/<folder>` through exactly one root key and ignores any file whose root key it does not recognise — with no line in `error.log`. These files declared `DIPLOMATIC_PACTS` and `RELATIONS`, neither of which is a history root key, so the Mod's entire starting diplomatic layer was inert: JHG was never a tributary of SHU, NMG was never a protectorate of MEX, and none of the starting relation values applied. `DIPLOMATIC_PACTS` does occur in the installed game, but only as a localization/concept identifier, which is what made the mistake look plausible. All five files now use the only accepted key, `DIPLOMACY`, and the three files that carried two root blocks were merged into one. This matters beyond cosmetics: `ywc_startup_smoke.txt` asserts `is_subject_of = c:SHU` for JHG and `= c:MEX` for NMG, so Gate 3 could not have passed.
- The mod's own scripted test was the tell, and a real save was the proof: `artifacts/observe/manual-gate23-1836-shu-01/userdata/save games/autosave.v3` (game date 1836.4.1, real date 2026.9.12, `version="1.13.11"`, `mods={ "The Yongchang World" }`, 123138887 bytes, sha256 `4b87f3a32dbae6ecead7792043ceb69342ae3d51aeb597eefe3e2af6e1618be8`) contains `vassal first=156 second=167` for vanilla's TIB-under-CHI pact but no pact row at all linking SHU's country id 730 to JHG's 731. Direction is grounded in vanilla history rather than assumed — `common/history/diplomacy/00_subject_relationships.txt` declares `c:CHI ?= { create_diplomatic_pact = { country = c:TIB type = vassal } }`, and the save records `first=156` (CHI) `second=167` (TIB), so `first` is the overlord. Merging a subject and a relations block under one `DIPLOMACY` key, and repeating the same `c:TAG ?=` across files, is safe because vanilla already does both: 32 tags appear in two or more diplomacy files, and `00_subject_relationships.txt` repeats BIC and EGY three times each.
- `ywc_check.py` now enforces the contract instead of trusting review: `common/history/<folder>` may only use that folder's vanilla root key (derived from the installed game when `--game-root` is given, otherwise from a checked-in baseline), an unknown folder name is reported, and a history file with no top-level key at all is reported. The check is wired into `validate()`, so it runs in preflight and in the suite. Negative fixtures cover an invented root key, a misspelled folder, and a comment-only file. Full suite passes 317 tests (9 new in `tests/test_history_root_keys.py`); `ywc_check` and all four static preflight checks stay clean over the Mod's 44 history files.
