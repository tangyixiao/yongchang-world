# 《永昌世界》从垂直切片到可玩发行版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把现有十国内容垂直切片推进为地图、经济、日志、事件、AI 和发行证据均闭环的 Victoria 3 1.13.11 可玩 v0.1。

**Architecture:** 以 `data/scenario/ownership_overrides.json` 作为所有权改写的单一真源，由生成器产出完整 `00_states.txt`；国家内容按“大顺—靖海样板、其余八国扩展”实现。运行验收使用统一的观察证据格式，严格区分静态测试、隐藏预加载、新开 1836 战局和长期观察局。

**Tech Stack:** Victoria 3 1.13.11 (Matcha), Build ID 24799966, Clausewitz/Jomini 脚本, YAML 本地化, JSON 场景数据, Python 3 标准库 unittest, Windows PowerShell 5.1, Git。

**Spec:** `docs/superpowers/specs/2026-09-04-00-世界观总纲.md`、`docs/superpowers/specs/2026-09-04-01-1644至1836历史年表.md`、`docs/superpowers/specs/2026-09-04-02-1836开局剧本.md`、`docs/superpowers/specs/2026-09-04-03-Mod技术框架.md`

## Global Constraints

- 固定开发基线为 Victoria 3 `1.13.11 (Matcha)`、Steam Build ID `24799966`。
- 本体目录 `E:\SteamLibrary\steamapps\common\Victoria 3` 只读，不修改本体文件和兼容层 DLL。
- 保留北清、靖海、东明、新明、卫拉特、喀尔喀、西藏、朝鲜、兰芳及南洋体系，不把设定收缩成“大顺替代大清”。
- 大顺控制汉地主要省份，但不自动取得蒙古、新疆、西藏、青海草原和全部西南山地。
- 北清开局人口保持三万至六万；新明是墨西哥争议自治属邦；靖海是大顺高自治藩国。
- 无 DLC 路径必须完整可玩；`ep1_content`、`mp1_content`、`ep2_content`只提供增强。
- 不预定 1900—1950 的政治结局，长期烟测允许国家合理独立、合并或灭亡。
- 不用免费修正掩盖州、人口、建筑、市场或外交的错误。
- 所有新脚本键使用 `ywc_` 前缀；国家 TAG 除外。
- 每个实施任务先增加会失败的验证，再做最小实现；每个提交只包含该任务文件。
- 开始实施前先保护当前未提交改动。规划编写时观察到的 13 个修改文件仅有行尾差异，执行者不得批量恢复、格式化或顺带提交它们。

## 当前判断

仓库已有十国定义、日志端点、事件、本地化、AI 接口、DLC 门禁、静态检查和隐藏启动工具，但目前仍是“内容可加载的垂直切片”，不是已验收的完整剧本：

- 大顺运行时只明确拥有北京和东北若干州，大量汉地仍属于原版 `CHI`，与规格冲突。
- `core_states.json`、区域账本和运行时 `00_states.txt` 对库页岛归属存在冲突，测试尚未跨账本核对最终运行时结果。
- 多数日志按月直接弹出结果事件；选项主要只设置成功、失败或放弃变量，缺少前置、过程、成本和持续后果。
- 观察汇总器与发布门禁使用不同的 `runs` 数据结构；当前命令链即使补齐证据也无法正确放行。
- 现有种子值主要用于目录和元数据，尚未证明它们实际控制游戏随机数。
- 地图拼花和事件按钮的静态修复尚需新开 1836 战局复核；15 组长期观察仍无真实检查点。
