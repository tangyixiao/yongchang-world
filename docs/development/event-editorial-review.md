# 《永昌世界》事件编审

供事件和日志的作者、译者及审稿人使用。新写一条线先审选题，返修旧线先把同一玩家在一局里可能连续收到的标题排在一起读。一个人可以写初稿，内容 PR 里应当看得出另一位读者为什么愿意保留这一幕，或建议把它并到哪里。

## 动笔前决定哪些事值得弹窗

先用两句话讲给没读过脚本的人听。谁在什么处境下做了什么？为什么这个玩家此刻值得为它停一下？例如矿主在工人保护法立法时联名求豁免，玩家一看便知道谁在向政府施压。官方对照可在游戏安装目录 `game/events/law_events/law_events.txt` 中找 `law_events.5`，在 `game/localization/simp_chinese/events_l_simp_chinese.yml` 中读同名正文和两种答复。

| 读过整条线后的判断 | 编辑动作 |
|---|---|
| 有人采取了行动，迫使玩家在两种利益、权利或承诺间取舍 | 保留为决策事件，逐个追问选项会改变谁的处境 |
| 一首歌、一则讣闻或一封家书让人看到这个国家独有的生活 | 可以只用一张风味事件、一个回应；写清出现时机，控制重复 |
| 数月经营、改革或谈判需要玩家持续留意 | 放入日志，列出目标和进展，在出现意外或需要重新选择时弹窗 |
| 登记、缴费、等候回函只是兑现上一项决定 | 费用写进原选项提示，执行并入日志动作或效果；重复告知同一结果的窗口删去 |

在 PR 里给待合并的旧节点写明承接位置、已打开的日志和待答事件如何继续。保留兼容所需的旧 ID。旧表中的配额用于盘点内容；同一决定拆成多次通知不能补缺。编辑后若低于目标，照实列明差额，另找独立题材或提出修改预算的理由。

## 写清楚凭据，也给创作留位置

在现有卡片或 PR 里记三件事即可。同一条线上可以共用出处。

1. **可考的历史。** 写明来源、年代、地区、原文所在卷页或条目，以及它支持哪一个细节。碑是谁立的、奏折是谁写的，会影响我们听见哪一方的声音。无法查明时，收窄断言或标作待考。
2. **本作的世界线。** 对照[历史年表](../superpowers/specs/2026-09-04-01-1644至1836历史年表.md)和[1836 开局](../superpowers/specs/2026-09-04-02-1836开局剧本.md)，说明这个地方还由谁统治、谁有权裁决、玩家当下满足什么条件。史实分歧之后，现实中的法令、国名和人物遭遇都需要重新判断。
3. **作者的创作。** 指出哪些人物、场景和对白是虚构。原话需要可追溯的出处。读者从正文体会人物处境，考据和创作说明留给审稿人。

**大顺机房的实审例。** 在[大顺目录](../../data/content/v03/countries/shu.json)里找 `ywc_shu.1111`。这一步让玩家缴登记费、暂缓或撤回，付清才进下一步。编审意见是把交费并入机房日志的受理动作，保留筹款和撤回的余地。实现时要验证旧窗口不会重复扣款。这是对现行事件的修改意见。

若想写一张机工自己的事件，可以从一个有出处的争端起笔。1734 年苏州机户立《永禁机匠叫歇碑》。地方志部门记述了计件给酬、按质量调整工价，以及机户求官府禁歇的经过。碑留下了机户的立场。清廷在这一年做过的裁决，只能给架空大顺提供一个参照。[碑刻图录](https://www.jnwhcn.net/ImageDetail.aspx?ArticleId=d2ef2074-5c16-49da-a90c-a154b9801efd) · [苏州市地方志办的记述](https://dfzb.suzhou.gov.cn/dfzb/gzdt/200909/d4934a67b0564dcca21e8101fabe6eae.shtml)

下面是取材于这种工价纠纷的原创试笔，呈堂的这匹缎子和人物举动均属虚构。

> 机户请县里出榜禁歇，说已经三天招不到一个上机的人。堂下的织工放下半匹青缎。他认得布边那根错丝，是自己接的头。掌柜为它扣了一匹的工钱，如今要见官，他倒盼着掌柜把那根丝找出来。

若只查到一桩地方争执，写到这里就能作为州内见闻。若要朝廷裁决，就要写出事态为何扩大，例如数县机户联名求颁通例，并让禁歇或受理工价申诉确实影响相应人群。这个候选题材只适用于有丝织业与相应劳资关系的地区。当前机房线也允许食品加工业和其他州进入，不能把苏州故事套在全部开局上。

## 写到玩家实际读到的地方

- **标题和正文。** 先落到一个动作、一件东西或一句有来由的话。矿主会谈停工一天损失多少，织工关心一匹缎子拿得到几文。选一处能揭示利害的细节，给读者留下判断余地。遮住国名再读一遍，若换个国家依旧字字合用，回查当地人靠什么生活、向谁说理。
- **选项和提示。** 按钮让玩家表态，提示说明谁出钱、谁能拒绝、什么会改变。对方还要独立作答时就写“发出邀请”。“达成协议”要等双方真的同意。凡是提到工资、集团态度或国库的后果，顺着对应选项找到写入效果或后续读取处。
- **双语成稿。** 同读中英文正文、按钮、费用和后果。两种语言要让玩家面对同一个决定，人物语气各自读得自然。v0.3 目录使用 `desc` 容纳叙事，`purpose` 留给作者。玩家会读到 `cost_note` 和 `consequence_note`，变量名、测试术语和“记录本次决定”都应改成具体含义。

## 内容 PR 如何验收

作者在现有 PR 描述中贴一张代表卡的双语成稿或对应差异，并简记 **选题处置与缘由 / 史料、世界线与虚构 / 选项对应的脚本后果**。多个相似的手续可以合并说明。审稿人从玩家看到的第一句一路读到结果，指出还欠哪条证据、哪句话有问题或哪一步重复；作者修改后回读同一处。有争议的史实或未实现的效果留为待修，别写成已验收。

按所改内容选择检查。在 v0.3 目录重新生成该单元后，运行 `python tools/build_v03_content.py --check` 和 `python tools/ywc_v03_check.py --json`。大型战役、天命霸权、西南六国各用 [README 对应章节](../../README.md)列出的生成器和验证工具。手写事件直接核对所改脚本及两种本地化，按 [README 的开发验证](../../README.md#开发验证)运行通用 `ywc_check.py`。

改过费用、派送或旧入口时补跑相应行为回归。PR 分开记下编审意见、实际运行的检查以及已有的游戏内观察。实际弹窗频率和连读体验要由相应战局记录证明。
